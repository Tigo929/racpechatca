# Отправка согласований в Telegram

В карточке заказа-футболки, в разделе «Согласование макета с клиентом»,
кнопка **«Отправить клиенту на согласование»** появляется при способе связи
**Telegram**. Доступ: администратор и менеджер по оформлению.

1. В контакте заказа укажите `@username` или `https://t.me/username` клиента.
2. Создайте согласование и сформируйте изображение кнопкой «Готово».
3. Нажмите «Отправить клиенту на согласование» рядом с версией макета.
4. Дождитесь статуса «Отправлено в Telegram». Ответ клиента придёт в обычную
   переписку рабочего аккаунта. Отправка сама по себе не означает согласование.

Текст сообщения:

> Здравствуйте! Подготовили макет для заказа №… (версия …) и отправляем его на согласование.
>
> Пожалуйста, проверьте изображение, расположение и размер принта, а также цвет и размер изделия.
>
> Если всё верно, ответьте «Макет согласован». Если нужны изменения, напишите, что следует скорректировать.
>
> Передадим заказ в печать после вашего подтверждения.

## Повторная отправка и ошибки

- Одна версия отправляется один раз. Для исправлений создайте новую версию.
- При подтверждённом отказе (не найден контакт, приватность, ограничение Telegram)
  CRM показывает причину и разрешает явное повторное нажатие после исправления.
- Если связь оборвалась во время отправки, автоматического повтора нет. CRM
  показывает «Результат отправки не подтверждён»: сначала проверьте переписку.
- Клиент должен быть личным аккаунтом. Группы, каналы, боты, собственный аккаунт
  отправителя, приглашения и ссылки на отдельные публикации не поддерживаются.
- Телефон без username не используется как адрес: это предотвращает отправку
  неверному получателю. Укажите ссылку на личный Telegram клиента в заказе.

## Устройство

`POST /order-photo-approvals/:id/send-telegram` защищён JWT и ролями.
Адрес берётся из заказа на сервере. Изображение сохраняется в очереди PostgreSQL
как отдельный снимок JPEG, до 2560 px / 10 МБ. Исходный PNG для скачивания сохраняется.
Последующие правки макета не изменяют поставленное в очередь изображение.

Один `ApprovalTelegramDelivery` на версию, блокировка строки при постановке,
`FOR UPDATE SKIP LOCKED` при получении задачи. Клиент получает только статус,
адресата и даты; машинный claimToken и содержимое изображения не возвращаются
в списке согласований. Успешная отправка сохраняет Telegram messageId.

Воркер `greeter/approval_delivery.py` использует уже авторизованную Telethon-сессию.
API `/order-photo-approval-delivery/{claim,:id/image,:id/complete}` использует
существующие CRM_LEAD_TOKEN и HMAC-подпись. Новые секреты не нужны.

Зависшие SENDING старше пяти минут переходят в UNKNOWN при следующем опросе.
Повторяется только подтверждение результата, а не отправка изображения.
Позднее успешное подтверждение может перевести UNKNOWN в SENT.
Флаг APPROVED вручную ставится только после ответа клиента.

## Выкатка

Перед обновлением сохраните резервную копию БД и ID действующих образов.
Сначала обновляется backend с добавочной миграцией
`20260919120000_approval_telegram_delivery`, затем greeter и frontend.
Сборку backend/frontend выполняет GitHub Actions; сборку на слабом сервере не запускайте.

Greeter собирается отдельно из `greeter/Dockerfile`; при обновлении нужно включить
`approval_delivery.py`, обновлённый `tg_greeter.py` и requirements.txt.
Том `greeter_session` сохраняется. Не запускайте два клиента с одной сессией.
Существующие файлы текстов приветствия и настройки прокси сохраняются.

Откат: восстановить предыдущие образы backend/frontend/greeter. Новая таблица
совместима со старым backend; удалять её для отката не требуется. Перед откатом
остановить greeter и проверить незавершённые отправки. После замены backend
перечитать nginx, чтобы обновился адрес upstream.

## Проверки

- Backend: `npm test -- --runInBand`, `npm run build`.
- Frontend: `npm test`, `npm run build`.
- Greeter: `python -m unittest test_approval_delivery test_signing test_proxy_config test_greeting_text`.
- Интеграционная проверка на отдельной PostgreSQL-базе: одновременные клики и
  захват задач, неизменность картинки, потерянный ответ воркера, позднее
  подтверждение, проверка токена/HMAC и DTO. Реальным клиентам тесты не пишут.
