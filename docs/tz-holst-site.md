# ТЗ: раздел «Печать на холсте» на raspechatkaa.ru

Составлено 19.08.2026 по результатам разбора четырёх конкурентов.
Исполнитель — ИИ. Блоки выполнять **по порядку**: каждый следующий опирается
на предыдущий. Внутри блока пункты можно делать параллельно.

---

## Блок 0. Контекст и границы

**Что уже есть.** Сайт `raspechatkaa.ru` — фотопечать, 10 форматов, у каждого
своя посадочная с калькулятором тиража и формой заявки. Заявка уходит в CRM.
Разметка Product/FAQPage/BreadcrumbList/Organization стоит, sitemap есть.

**Что добавляем.** Второй продукт — холст. Модель `ItemCanvas` в CRM уже
существует (`formatCanvas`, `clientPrice`, `contractorPrice`, `profitPosition`),
сценария оформления нет.

**Чего НЕ делаем в этой итерации:** футболок на сайте, полноценного графического
редактора, онлайн-оплаты. Обоснование — в блоке 11.

**Кого разбирали:**

| # | Сайт | Кто это | Насколько релевантен нам |
|---|---|---|---|
| 1 | netprint.ru | Федеральный фотосервис, с 2004 | Высоко — та же бизнес-модель |
| 2 | multifoto.ru | Федеральный фотосервис, своё производство | **Максимально** — эталон механики |
| 3 | kopirka.ru | Сеть копицентров, 370+ офисов | **Максимально** — эталон SEO-структуры |
| 4 | mdmprint.ru | B2B-типография | Низко — берём только 2 приёма |

Оговорка: точных цифр по трафику получить не удалось, ранжирование выше —
по наблюдаемым признакам (глубина каталога, охват, зрелость SEO-структуры),
а не по данным счётчиков.

## Блок 1. Информационная архитектура и URL

**Что делают конкуренты.**

Все трое релевантных строят трёхуровневую иерархию, а не плоский список:

```
netprint   /moscow/interior/photo-canvas        ← город в URL
           /moscow/interior/photo-canvas-premium
           /moscow/interior/acrylic-glass, /pechat-na-pvh, /pechat-na-dereve

multifoto  /fotopechat/interernaya/holsty/      ← раздел / подраздел / товар

kopirka    /uslugi/framing/                     ← описание услуги
           /catalog/foto-na-holste/             ← каталог товаров
           /printing/foto-na-kholste-30kh40-sm/designer/  ← конструктор размера
```

Ключевое наблюдение: **у всех «холст» — это не одна страница, а куст страниц.**
У Копирки каталог холстов занимает 9 страниц пагинации (135+ позиций), у каждого
размера свой URL с конструктором.

**Что делаем.**

Ввести уровень «интерьерная печать» сразу, даже если пока в нём только холст —
чтобы потом добавить акрил и дерево без переезда URL.

```
/interer/                          хаб раздела
/interer/holst/                    хаб продукта (главная посадочная)
/interer/holst/30x40/              карточка размера
/interer/holst/40x60/
/interer/holst/50x70/
/interer/holst/60x90/
/interer/holst/30x40/zakaz/        конструктор + заявка
```

Существующий фото-каталог не трогаем: `/catalog/<формат>` остаётся как есть.

**Критерий готовности:** все URL отвечают 200, старых редиректов не появилось,
sitemap.xml пополнен новыми адресами.

## Блок 2. Хлебные крошки и связность

**Что делают конкуренты.**

- netprint: `Главная → Интерьерная печать → Печать на холсте`
- multifoto: `Главная → Фотопечать → Интерьерная печать → Печать на холсте`
- mdmprint: `Главная → Каталог услуг → Широкоформатная печать → Интерьерная печать → Печать на холсте` (5 уровней, размечено `BreadcrumbList`)
- kopirka: `Главная → Фото на холсте` (2 уровня — слабое место, теряет вес)

**Что делаем.**

Крошки на всех новых страницах, минимум 3 уровня:

```
Главная → Интерьерная печать → Печать на холсте → Холст 30×40
```

Каждый элемент — ссылка, последний — текст без ссылки. Размечать `BreadcrumbList`
(механизм на сайте уже работает, переиспользовать).

**Перелинковка — обязательная часть, не украшение.** На карточке размера:

1. Блок «Другие размеры» — ссылки на все остальные размеры холста.
2. Блок «Смотрите также» — ссылка на фотопечать (обратный ход воронки).
3. В тексте — ссылка на хаб `/interer/holst/`.

На хабе холста — ссылки на все карточки размеров + на тематические лендинги
(блок 8). Так вес перетекает вниз, а пользователь не упирается в тупик.

**Критерий:** с любой страницы холста можно за один клик попасть на любой другой
размер и на хаб.

## Блок 3. Хаб продукта `/interer/holst/`

Главная посадочная под запрос «печать фото на холсте москва».

**Что делают конкуренты — порядок блоков.**

Multifoto (самая проработанная страница) идёт так:

1. H1 + цена «от» + количество отзывов + короткое описание сути
2. Выбор формата + количество + **итоговая цена сразу**
3. «Что входит в комплект» (холст / подрамник / крепление)
4. «Как мы создаём холсты» — три шага производства с фото
5. Оборудование и качество печати
6. Популярные размеры (плитки-ссылки)
7. «Для чего нужна печать на холсте» — сценарии применения
8. Дополнительные услуги (багет)
9. Таблица цен по всем размерам
10. FAQ
11. Отзывы с фото пользователей
12. Преимущества (оплата, анонимность, перепечатка брака, доставка)

Kopirka: галерея → характеристики → таблица цен → **срок и срочность** →
художественная отрисовка → мини-мольберт → онлайн-конструктор → каталог
готовых дизайнов → оплата/доставка → карта офисов → отзывы.

Netprint: минималистично — фото, цена со скидкой, селектор формата, селектор
багета, описание, характеристики. Всё продающее вынесено в конфигуратор.

**Что делаем.** Порядок блоков на нашем хабе:

1. **H1 «Печать фото на холсте в Москве»** + «от N ₽» + срок изготовления
2. **Селектор размера с живой ценой** — не таблица, а кликабельные плитки; цена меняется мгновенно. Это главный экран, он должен быть виден без прокрутки.
3. **«Что входит в цену»** — холст, подрамник, натяжка, крепление в комплекте. Копируем Multifoto: клиент боится, что подрамник и крепёж докупать отдельно.
4. **Как это делается** — 3 шага с фотографиями реального производства.
5. **Требования к фото** — какое разрешение нужно для какого размера. Таблица «размер → минимальный размер файла в пикселях». Снимает главное возражение «а моё фото подойдёт?».
6. **Все размеры и цены** — таблица, каждая строка ссылкой на карточку размера.
7. **Допродажи** — багет, мольберт, срочное изготовление (блок 6).
8. **Сценарии применения** — подарок, интерьер, портрет, репродукция.
9. **FAQ** — минимум 6 вопросов (блок 9).
10. **Доверие** — отзывы, гарантия перепечатки, анонимность (блок 7).
11. **SEO-текст** внизу, 2–3 абзаца.

**Критерий:** цена видна в первом экране; до формы заказа не больше одного клика.

## Блок 4. Карточка размера `/interer/holst/30x40/`

**Зачем отдельные страницы под размер.** Kopirka и Multifoto делают именно так,
и это правильно: запрос «холст 30х40 фото» — самостоятельный, частотный, и
общая страница по нему проигрывает специализированной.

**Состав карточки:**

- H1 «Холст 30×40 с вашим фото»
- Цена крупно, фиксированная за штуку (не тираж)
- Визуализация: холст 30×40 в интерьере, чтобы был понятен масштаб
- «Подойдёт для» — какое фото хорошо смотрится в этом размере
- Требование к файлу именно для этого размера, в пикселях
- Кнопка → конструктор `/interer/holst/30x40/zakaz/`
- Блок «другие размеры»
- Разметка `Product` с `offers.price`

**Критерий:** страница самодостаточна — на неё можно приземлять рекламу.

## Блок 5. Приём файла — ядро продукта

**Что делают конкуренты.** Это главный вывод всего анализа:

| Сайт | Как клиент передаёт фото |
|---|---|
| multifoto | Конструктор на поддомене `p.multifoto.ru/printing/canvas-2/30x40-prem/editor`: загрузка, кроп, текст, фон, коллажи, стикеры, рамки, **линии безопасности**, блок «Ошибки», предпросмотр, «В корзину за 3 517 ₽» |
| kopirka | Конструктор `/printing/foto-na-kholste-30kh40-sm/designer/` + альтернативы: «Прислать макет», шаблоны PDF/CDR/PSD, «нет шаблона — сделаем дизайн от 1500 ₽» |
| netprint | Конфигуратор с выбором формата и багета, дальше редактор |
| mdmprint | **Только через менеджера** — заявка, мессенджер, «требования к макетам» отдельной страницей |

**Три из четырёх принимают файл на сайте до оплаты. Через менеджера работает
только B2B-типография.** Наша текущая схема («менеджер напишет и примет
фотографии в переписке») — это модель МДМпринта, то есть модель типографии,
а не фотосервиса.

**Что делаем — минимальный конструктор, не редактор.**

Полный редактор Multifoto — это месяцы работы. Нам нужно 80% пользы за 5% усилий:

1. Экран `/interer/holst/<размер>/zakaz/`
2. Загрузка одного изображения (drag&drop + кнопка, обязательно работает с телефона)
3. Автоматическая подгонка под пропорцию размера + возможность подвинуть/зумировать рамку кадрирования
4. **Проверка разрешения**: если файла не хватает на выбранный размер — жёлтое предупреждение «для 60×90 нужно минимум X×Y px, у вас меньше — возможна нерезкость» + предложение выбрать размер поменьше. Это прямая калька с блока «Ошибки» у Multifoto и снимает главную причину брака.
5. Показ линий безопасности: что уйдёт на боковую грань подрамника при натяжке. Клиент должен видеть, что головы не обрежет.
6. Итоговая цена + допродажи (блок 6)
7. Форма заявки — переиспользовать существующую с фото-страниц
8. Оставить запасной путь как у Kopirka: «нет фото под рукой — оставьте заявку, менеджер примет файл в переписке». Не все грузят с первого раза.

**Критерий:** клиент со смартфона проходит путь «выбрал размер → загрузил фото →
увидел кадрирование → отправил заявку» без участия менеджера.

подрядчика — в `contractorPrice`, чтобы `profitPosition` считался честно.

## Блок 7. Доверие и снятие возражений

**Что делают конкуренты.**

- multifoto: «Бесплатно перепечатаем брак», «100% анонимность — производство автоматизировано, никто не увидит твои снимки», срок хранения файлов, отзывы с фотографиями пользователей, рейтинг с разбивкой по звёздам
- kopirka: 370+ офисов, карта, свежие отзывы с датами, «собственное производство»
- netprint: «Национальный сервис №1 в России по количеству пользователей», с 2004 года
- mdmprint: **«Ещё нет отзывов»** — и это на продающей странице. Антипример.

**Что делаем.** У нас уже сильнее всех: 403 отзыва со ссылками на Яндекс.Карты
и Авито — то есть проверяемые на чужих площадках, а не написанные самими.
Этот блок переносим на страницы холста без изменений.

Добавить специфичные для холста возражения:

1. «А моё фото подойдёт?» → таблица разрешений + автопроверка в конструкторе
2. «Не обрежет ли головы при натяжке?» → показ линий безопасности
3. «Подрамник и крепление входят?» → «Что входит в цену»
4. «Что если не понравится?» → наша гарантия перепечатки, уже сформулированная
5. «Куда денутся мои фото?» → у нас уже есть «не публикуем, удаляем после печати»

**Наше преимущество, которого нет ни у кого из четверых: оплата после
подтверждения.** Все конкуренты требуют онлайн-оплату вперёд. Вынести это на
холсте так же заметно, как на фотопечати — на чеке в тысячи рублей это работает
сильнее, чем на заказе за 200 ₽.

## Блок 8. Тематические и сезонные лендинги

**Что делает Kopirka** — и это лучшая находка всего анализа. Помимо каталога
размеров, у неё отдельные посадочные под поводы:

```
/catalog/pechat-foto-na-kholste-k-novomu-godu/
/catalog/pechat-foto-na-kholste-k-8-marta/
/catalog/fotokollazh-na-kholste/
/catalog/izgotovlenie-posterov-na-kholste/
/uslugi/mini-holsty/  +  /catalog/mini-kholst/
```

Один товар — много входов. Человек ищет не «холст», а «подарок маме на Новый год».

**Что делаем.** Сразу, до сезона:

1. `/interer/holst/v-podarok/` — холст как подарок, общая
2. `/interer/holst/novyy-god/` — **приоритет, запустить до 1 ноября**, со сроком «успеем к 31 декабря, крайняя дата заказа — N декабря»
3. `/interer/holst/portret/` — портрет на холсте
4. `/interer/holst/kollazh/` — несколько фото на одном холсте

Каждый лендинг ведёт в тот же конструктор. Дублирования контента избегать:
у каждого свой текст, свои примеры, свой оффер.

**Критерий:** новогодний лендинг проиндексирован не позже 5 ноября — иначе
сезон пройдёт мимо.

## Блок 9. SEO-разметка и техничка

**Что у конкурентов.**

| Сайт | Микроразметка |
|---|---|
| mdmprint | `Organization`, `LocalBusiness`, `BreadcrumbList`, `Product` |
| multifoto | `Product`, `FAQPage`, `ImageGallery`, `Organization`, `LocalBusiness` |
| netprint | нет ld+json на странице холста |
| kopirka | нет ld+json на странице холста |

Двое из четырёх не размечены вообще — там есть куда влезть.

**Что делаем.** На каждой странице холста:

- `Product` с `name`, `image`, `description`, `sku`, `offers` (цена, валюта, `availability`)
- `BreadcrumbList` по блоку 2
- `FAQPage` на хабе — минимум 6 вопросов: разрешение фото, что такое галерейная натяжка, матовый или глянцевый, входит ли крепление, срок изготовления, можно ли фото с телефона
- `LocalBusiness` с московским адресом — **добавить обязательно**, сейчас «Москва» встречается на сайте один раз, локального сигнала нет
- `AggregateRating` на основе реальных 403 отзывов

Title по образцу лидеров: `Печать фото на холсте в Москве — от N ₽ | Распечатка`.
Meta description с ценой, сроком и телефоном — так делают все четверо.

**Техническое:**

- все новые URL в sitemap.xml
- изображения в WebP с осмысленным alt
- LCP < 2.5 с (конструктор грузить отдельным чанком, не блокировать первый экран)
- мобильная версия — приоритет: фото приходят с телефона

## Блок 10. Интеграция с CRM

1. `crm-new/src/scenarios/products/canvas.scenario.ts` — какие вопросы задаём: размер, материал (мат/глянец), багет, срочность, комментарий.
2. `crm-new/src/scenarios/products/canvas.mapper.ts` — превращение ответов в `ItemCanvas`.
3. Строка в `scenario.registry.ts`. Фронтенд CRM не трогаем — механизм это позволяет.
4. Заявка с сайта приходит с уже загруженным файлом: ссылка на файл кладётся в заказ, менеджер не собирает фото в переписке.
5. `contractorPrice` заполняется по прайсу подрядчика — тогда `profitPosition`
   показывает реальную маржу по каждому холсту и через месяц будет видно,
   какие размеры продавать, а какие убрать.

## Блок 11. Что НЕ делать

- **Не строить редактор уровня Multifoto** (текст, стикеры, рамки, коллажи, фоны). Это команда и месяцы. Нужен кроп + проверка разрешения.
- **Не делать 135 размеров как Kopirka.** Начать с 4–6 ходовых: 30×40, 40×60, 50×70, 60×90, плюс квадрат 30×30 и 50×50. Расширять по спросу, который покажет `profitPosition`.
- **Не заводить онлайн-оплату** в этой итерации. «Без предоплаты» — наше отличие от всех четверых, и оно же экономит нам эквайринг и 54-ФЗ.
- **Не дублировать цену в двух местах.** Ошибка Kopirka: 4 120 и 3 700 за один товар на одной странице.
- **Не оставлять пустой блок отзывов.** Ошибка MDMprint. Либо наполнен, либо его нет.
- **Не трогать футболки.** Они на Ozon, на сайте они не дадут нового спроса.

## Блок 12. Технологическое преимущество

Блоки 1–11 позволяют сравняться с конкурентами. Этот блок — про то, за счёт
чего их обойти.

**Исходная позиция конкурентов.** Все четверо построены на тяжёлых CMS прошлого
поколения: у Копирки в путях к файлам видно `/wa-data/public/site/oldimg/` —
Webasyst с папкой «старые картинки», у МДМпринта Битрикс-формы, Нетпринт живёт
с 2004 года. Мультифото — самый современный, у него отдельный поддомен под
конструктор и нативные приложения в сторах, но и он не использует ничего
из перечисленного ниже. **Их фора — накопленный SEO-вес и производство.
Наша единственная возможная фора — механика, которой у них нет.**

### Берём сразу, до сезона

| Технология | Что даёт | Почему конкуренты этого не делают |
|---|---|---|
| **Обработка изображения в браузере** (Canvas API, `createImageBitmap`, WebCodecs) | Кроп, поворот и проверка разрешения происходят на устройстве. На сервер уходит уже подготовленный файл, а не 40-мегабайтный оригинал | Их конструкторы серверные, писались до того, как браузер это умел |
| **Умный кроп по лицам** (`FaceDetector` / MediaPipe Face Detection) | Рамка кадрирования сама встаёт так, чтобы натяжка на подрамник не срезала головы. Это главный страх клиента при заказе портрета | Ни у кого из четверых нет — у всех кроп ручной |
| **Превью холста на стене** (CSS 3D-перспектива поверх фото интерьера, либо Three.js) | Клиент видит свой снимок висящим в комнате в реальном масштабе. Прямо отвечает на вопрос «а 30×40 — это много или мало?» | Никто из четверых не показывает результат в интерьере с фото клиента |
| **Возобновляемая загрузка** (chunked / tus, Service Worker) | Файл на 50 МБ с мобильного интернета не отваливается на 90%. Дозагрузится после потери связи | Классическая форма `multipart/form-data` рвётся |
| **Telegram Mini App для загрузки** | Клиент кидает фото в чат — заказ создаётся в CRM. Ни регистрации, ни приложения. У нас **уже есть** Telegram-интеграция и `GulianOutbox` | У всех четверых вход только через сайт или нативное приложение |
| **PWA + Web Share Target** | «Поделиться» из галереи телефона прямо в наш сайт. У Мультифото ради этого два нативных приложения в сторах — PWA даёт то же почти бесплатно | Дорого поддерживать нативку, дёшево — PWA, но их стек этого не умеет |
| **Next.js SSG/ISR** | Страницы отдаются статикой, Core Web Vitals в зелёной зоне. Скорость — фактор ранжирования, а сайты на Битриксе и Webasyst тяжёлые | Переписывать legacy никто не будет |

### Берём после сезона

| Технология | Что даёт | Риск |
|---|---|---|
| **ИИ-апскейл фото** (Real-ESRGAN и аналоги) | Снимает главное возражение «моё фото не потянет 60×90». Превращает отказ в **платную опцию** и продажу большего размера: «фото маловато — улучшим за N ₽, тогда возьмёте 60×90» | Нужны свои мощности или внешний сервис; проверять качество на портретах вручную |
| **AR-примерка** (`<model-viewer>`, WebXR) | С телефона навести камеру на стену и увидеть холст в реальном размере | Работает не на всех устройствах, нужен запасной путь |
| **Генерация посадочных под длинный хвост** | Копирка собирала 135 страниц каталога годами. Структуру «размер × повод × сюжет» можно развернуть быстро | Штампованные тексты ловят фильтры. Генерировать каркас, писать смысл руками |
| **Сквозная аналитика до маржи** | В CRM `profitPosition` считает прибыль по каждой позиции. Связать источник трафика с **прибылью**, а не с числом заявок | Требует разметки UTM на всех входах |

### Правило приоритета

Брать в первую очередь то, что **видно клиенту в момент выбора**: умный кроп,
предупреждение о разрешении, превью на стене. Инфраструктурное (загрузка,
PWA, скорость) — фоном. ИИ-апскейл — самое денежное, но и самое долгое,
поэтому после сезона.

**Критерий:** клиент, зашедший с телефона, должен получить опыт, которого
у конкурентов физически нет — увидеть свой снимок на своей стене и получить
честное предупреждение о качестве до того, как заплатит.
