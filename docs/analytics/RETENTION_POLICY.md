## 3. Политика (RETENTION_RULES)

| Таблица | Статусы | Хранить | Обоснование |
|---|---|---|---|
| MetrikaSyncRun | SUCCESS | 90 дней | свежесть и диагностика смотрят на часы; аудит — на квартал |
| MetrikaSyncRun | FAILED, PARTIAL | 365 дней | evidence инцидентов |
| AnalyticsInsightRun | SUCCESS, SKIPPED, LOCKED | 90 дней | часовые запуски без ошибок; карточки и версии не трогаются |
| AnalyticsInsightRun | FAILED | 365 дней | evidence |
| MetrikaOrderOutbox | delivered, skipped | 180 дней | сопоставление с `uploading_id` Метрики нужно полгода |

**Никогда** (явный список `RETENTION_NEVER`): MetrikaDaily* (это данные дашборда; пресет 365 дней и окна этапов 11–12
читают историю), снимки пресетов (upsert), AnalyticsChange / AnalyticsChangeEvaluation (аудит этапа 11),
AnalyticsInsight / AnalyticsInsightVersion (жизненный цикл и аудит этапа 12), MetrikaOrderOutbox в статусах
pending / processing / failed (незакрытые переходы; failed ждёт оператора).

Свойства: детерминированность (одинаковый `now` → одинаковый план — тест), удаляются только завершённые строки старше
порога по `startedAt` / `processedAt`, ошибки живут дольше успехов, пресеты дашборда (7/30/90/365 дней), окна этапов
11 (7/14/28 дней) и 12 (7/7, будущие 28/28) не затрагиваются, потому что данные не удаляются.

## 4. Dry-run и применение

```bash
npm run analytics:retention                 # dry-run: JSON-план (правило, порог, число строк), никаких записей
npm run analytics:retention -- --apply      # удаление; отказ без ANALYTICS_RETENTION_APPLY=1 в окружении
```

Сегодняшний dry-run на production **не запускался из контейнера** (код этапа 13 ещё не выложен); по замеру § 1 план на
17.09 пуст: самая старая строка MetrikaSyncRun — 12.09 (5 дней), правила начинают действовать с 11.12.2026 (90 дней).
Тесты: `retention.spec.ts` — правила, детерминизм, отказ без подтверждений, удаление ровно строк плана, прогноз.

## 5. Rollout retention (отдельный gate, не часть implementation)

1. После выкладки кода этапа 13 — `analytics:retention` (dry-run) внутри backend-контейнера, план в отчёт.
2. Первое применение — вручную в окне после тика, с `ANALYTICS_RETENTION_APPLY=1` только в команде (не в `.env`),
   результат (`deleted` по правилам) — в отчёт; повтор dry-run → 0.
3. Расписание (cron еженедельно) — только после двух ручных прогонов и решения Reviewer; рубильник — та же переменная.
4. Ротация логов Docker (`/etc/docker/daemon.json`: `max-size 50m`, `max-file 5`) — вместе с rollout этапа 13
   (сейчас json-file без ограничений; объёмы малы: 1,5 МБ / 7 дней у самого крупного контейнера).
