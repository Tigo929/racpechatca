## Что это

Один самодостаточный файл, который можно отдать внешнему ИИ и получить разбор бизнеса.
Отчёт не считает ничего своего: все числа приходят из принятых сервисов этапов 07–12
(`AnalyticsMetricsService`, `ReportsService`) — поэтому он совпадает с дашбордом до рубля.

```bash
npm run analytics:report                          # 7 дней, последний полный день
npm run analytics:report -- --period=30d          # другой размер текущего периода
npm run analytics:report -- --until=2026-09-21    # закончить конкретным днём
npm run analytics:report -- --out /tmp/report     # куда положить файлы
npm run analytics:report -- --stdout              # markdown в консоль, без файлов
```

Результат: `reports/analytics/<день>/analytics-report-<день>.md` и рядом `.html`.

Сбор и рендер разделены намеренно: модель и печать проверяются на синтетических данных
без базы, а сбор остаётся тонкой прослойкой над уже принятыми сервисами.

## Правила, заложенные в код

```text
1. Нет числа — печатаем «—», а не ноль. Прогноз без истории не строится:
   INSUFFICIENT HISTORY FOR RELIABLE FORECAST.
2. Причинность не утверждается. Вердикты INCOMPARABLE и causality: NOT_ESTABLISHED
   доезжают до отчёта как есть.
3. Деньги по источникам трафика не раскладываются, пока покрытие ClientID ниже порога, —
   печатается NOT ATTRIBUTABLE с объяснением.
4. Прибыль называется «по методике отчёта владельца», а не чистой бухгалтерской.
5. Персональных данных в отчёте нет по построению: в модель попадают только агрегаты,
   имён, телефонов, почты, IP, полных ClientID и yclid в ней не существует. Тесты
   дополнительно сканируют готовый markdown и html по шаблонам.
```

## PDF

PDF-файл напрямую не генерируется — осознанное решение, а не пропуск.

```text
ПОЧЕМУ:  единственный надёжный способ получить PDF из HTML в Node — headless-браузер
         (puppeteer/playwright): +300 МБ к образу, отдельный поток обновлений
         безопасности и ощутимая нагрузка на сервер с одним ядром. Ради файла,
         который нужен изредка, это дорого.
ЧТО ВМЕСТО: CLI кладёт рядом печатный HTML с постраничной вёрсткой (@media print).
         Браузер делает PDF одним действием: открыть → «Печать» → «Сохранить как PDF».
ГАРАНТИЯ: HTML собирается из ТОЙ ЖЕ строки markdown, что и .md, — расхождение форматов
         невозможно; тест сверяет ключевые числа в обоих файлах.
ЕСЛИ ПОНАДОБИТСЯ: отдельным заданием можно добавить генерацию PDF на машине владельца
         (без изменения production-образа).
```

## Ограничения

```text
- Деньги по источникам трафика посчитать нельзя, пока ClientID есть у меньшинства заказов.
- Рекламные расходы в систему не заводятся: CPL, CPA, ROAS, ROMI недоступны (не выдумываются).
- Медиана чека не выводится: её нет в контракте метрик, а считать своей формулой нельзя —
  разошлись бы с дашбордом.
- Прогноз — среднее по четырём последним полным неделям, без сезонности; при короткой
  истории не строится вовсе.
- UI-кнопки «сформировать отчёт» в панели нет: CLI полностью решает задачу, а лишний
  маршрут в дашборде — отдельное решение Reviewer.
```
