## 3. Правила обращения с секретами (действуют)

- Значения — только в `.env` (права 600) и `~/.aws/credentials`; в compose — только `${VAR}`; в репозиториях —
  `.env.example` без значений; в отчётах и логах — никогда (проверено сканом § 1).
- Клиент Метрики держит токен строкой только в момент формирования заголовка; в ошибках и логах — операция, код,
  длительность (тест I).
- Временные JWT для rollout-проб подписываются внутри контейнера (`process.env.JWT_SECRET`), живут ≤ 10 мин, не печатаются.
- Диагностика `/analytics/ops/status` не возвращает значения переменных, только флаги вкл/выкл и `metrikaConfigured: true/false`.
- Скрипты этапов на сервере (`/root/stage*/`) читают `.env` только в переменную процесса; вывод фильтруется `sed` по паролю.

## 4. Обнаружено при аудите сервера (не секреты, но hardening)

- `sshd`: `PasswordAuthentication yes` при одном ключе в `authorized_keys` — рекомендуется `no` (ключевой вход уже
  используется). Изменение — на сервере, отдельным решением владельца (не в scope аналитики).
- nginx access log сайта содержит `yclid=<19–20 цифр>` и IP — см. RELIABILITY_SECURITY_AUDIT.md § 2 (P2, rollout 13).
