# Достоверность значений аналитики — 28.09.2026

## Изменение

Общее предупреждение «себестоимость неполная» дополнено измеримыми причинами. `financials.evidence` содержит отдельные группы принятых, оплаченных по clientPaidAt и реализованных заказов: всего заказов, сколько не имеют пригодных позиций для расчёта затрат, стоимость затронутых заказов и их категории. Группы пересекаются; их суммы не складываются. Стоимость затронутых заказов не является оценкой недостающих расходов.

Выручка реализации разложена по фактически использованному основанию даты в каноническом порядке: clientPaidAt → completedAt → statusChangedAt → sentAt → createdAt. Каждому заказу соответствует ровно одна строка, сумма количества и выручки обязана совпадать с реализацией. Резервные даты не доказывают поступление денег.

Интерфейс и Markdown/HTML-отчёт показывают одинаковую детализацию. Прибыль названа расчётной; полнота позиций для расчёта не представляется процентом достоверности закупочных цен. Исправлены оставшиеся подсказки, называвшие достижения CRM-целей уникальными сопоставленными заказами. Расход рекламы действительно показывается отдельно — устранено ошибочное «не» в подписи.

Отчёт теперь оценивает неполноту затрат именно реализованной группы при сравнении прибыли. Заказ без позиций в ещё не выполненном остатке не блокирует вывод о прибыли уже реализованных заказов. При отсутствии новой детализации сохранено осторожное поведение старого контракта.

Это оборот с неполными затратами, не величина завышения прибыли.

Заказ 20260820-068 имеет сумму 1 ₽. Это основание для проверки назначения записи, но не доказательство тестового заказа: он не исключался из аналитики автоматически. Номера остальных: 20260807-021, 20260825-083, 20260825-086, 20260827-090, 20260901-013, 20260902-023.

Ни цены, ни даты, ни назначения заказов не менялись. Достоверные затраты и даты старых платежей могут быть восстановлены только по подтверждённым исходным сведениям.

## Проверки

Тесты проверяют приоритет пяти дат признания, равенство суммы выручки групп итогам, отдельную оценку принятых/оплаченных/реализованных заказов, оборот с неизвестными затратами и отсутствие ложной блокировки прибыли из-за незавершённого заказа. Проверены рендер блока в CRM, вывод в отчёт для ИИ, совместимость со старым контрактом и обе сборки.
