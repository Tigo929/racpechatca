# BEHAVIOR_RULES.md

# Правила «Требует внимания» поведенческого слоя (этап 10, разделы 10–13)

## Статус

```text
IMPLEMENTED 14.09.2026 — crm-new/src/analytics/behavior/behavior-rules.ts (пороги) и
behavior-compute.ts (computeIssues). Без LLM и обучаемых моделей: только прозрачные пороги.
```

## Принципы

1. Каждая карточка — три части: **Факт** (числа периода и их подписи), **Гипотеза** (всегда в
   сослагательной форме: «возможно», «данные это не различают»), **Что проверить** (действие). Поле
   `causality: 'NOT_ESTABLISHED'` и подпись в UI «Причина не установлена — это наблюдение по данным».
2. Правило молчит при малой выборке. Причина молчания попадает в `skipped[]` и показывается в разделе
   («Правила без вывода из-за недостатка данных»), чтобы тишина не читалась как «всё хорошо».
3. Сравнение с предыдущим периодом используется только если он целиком после даты доступности целей
   (`comparable()`), иначе правило работает по абсолютным порогам или пропускается.
4. Единица — целевые визиты; события не используются для порогов (кроме числа ошибок по полям в тексте факта).

## Пороги (`behavior-rules.ts`)

| Константа | Значение | Смысл |
|---|---|---|
| `MIN_SAMPLE_VISITS` | 30 | меньше — `LOW_SAMPLE`: доли показываются, не ранжируются, карточек нет |
| `MIN_STEP_ENTRANTS` | 20 | минимум визитов на входе шага, чтобы обсуждать конверсию шага |
| `MIN_FORM_ERROR_VISITS` | 5 | минимум визитов с ошибкой формы за период для всплеска |
| `MIN_LEADS_FOR_RATE` | 3 | минимум заявок для правил о доле заявок и выбора метрики разрыва устройств |
| `dropoffAttentionRate` | 90 % | 11.1 ATTENTION |
| `dropoffDeltaCriticalPp` | 15 п.п. | 11.1 CRITICAL: конверсия шага упала к сопоставимому периоду |
| `deviceGapAttentionRatio` / `deviceGapCriticalRatio` | 0,5 / 0,25 | 11.2 |
| `errorSpikeAttentionFactor` / `errorSpikeCriticalFactor` | ×2 / ×3 | 11.3 |
| `errorRateAttentionPct`, `errorRateMinFormStarts` | 30 %, 10 | 11.3 без сравнения |
| `landingUnderperformanceRatio`, `landingMinExpectedLeads` | 0,5, 3 | 11.4 |
| `leadRateAnomalyRelPct` | 50 % | 11.5 |

## Правила

### 11.1 `FUNNEL_DROPOFF` — большой отвал на шаге
- Для каждой воронки и каждого перехода между **измеренными** шагами, кроме перехода «визит → первое
  действие» (доля визитов, начавших форму, — природа трафика; её показывает сводка и проверяют 11.2/11.4/11.5).
- Условие: вход ≥ `MIN_STEP_ENTRANTS` и (`dropoffRate ≥ 90 %` или падение конверсии шага к сопоставимому
  периоду ≥ 15 п.п.).
- Severity: ATTENTION; CRITICAL при падении ≥ 15 п.п.
- Факт: «шаг A → B: X → Y визитов, конверсия шага P %, отвал D %[; в предыдущем периоде P′ %]».
- Гипотеза: барьер на шаге (форма, требования, цена, техническая ошибка) — данных о причине нет.
- Проверить: шаг вручную на телефоне и компьютере, ошибки формы за период, Вебвизор визитов, остановившихся на A.

### 11.2 `DEVICE_GAP` — разрыв телефон / компьютер
- Только при ≥ `MIN_SAMPLE_VISITS` визитов у обоих устройств. Метрика: конверсия визитов в заявку, если
  заявок у обоих в сумме ≥ `MIN_LEADS_FOR_RATE`, иначе доля визитов с началом формы.
- Условие: mobile / desktop ≤ 0,5 (или mobile = 0 при desktop > 0).
- Severity: ATTENTION; CRITICAL при отношении ≤ 0,25.
- Гипотеза: трудности с формой/страницей на мобильных **либо** иной состав трафика — данные не различают.
- Проверить: форма и путь до неё на 360–430 px, ошибки формы и источники трафика по устройствам.

### 11.3 `FORM_ERROR_SPIKE` — ошибки формы участились
- Только при визитах с ошибкой ≥ `MIN_FORM_ERROR_VISITS`.
- Условие: ×2 к сопоставимому периоду, или ошибок раньше не было, или доля ошибок от начавших форму
  ≥ 30 % при ≥ 10 начавших.
- Severity: ATTENTION; CRITICAL при ×3.
- Факт включает чаще всего отбивающее поле (параметр `field`).
- Проверить: ввод в это поле в разных форматах, Вебвизор визитов с ошибкой, разрез по устройствам.

### 11.4 `LANDING_UNDERPERFORMANCE` — страница входа даёт меньше заявок
- Только при средней конверсии сайта > 0, визитах страницы ≥ `MIN_SAMPLE_VISITS` и ожидаемых заявках
  (visits × средняя) ≥ 3.
- Условие: конверсия страницы ≤ 50 % средней по сайту.
- Severity: ATTENTION.
- Гипотеза: страница не ведёт к форме или её трафик иной по намерению — по данным не различить.
- Проверить: источники трафика страницы, путь до формы с неё, долю начавших форму.

### 11.5 `LEAD_RATE_ANOMALY` — резкое изменение доли визитов с заявкой
- Только при ≥ `MIN_SAMPLE_VISITS` визитов в обоих периодах, сопоставимом предыдущем периоде и
  ≥ `MIN_LEADS_FOR_RATE` заявок хотя бы в одном из них.
- Условие: относительное изменение ≥ 50 %.
- Severity: ATTENTION при падении, INFO при росте.
- Проверить: источники и страницы входа двух периодов, ошибки формы и серверные ошибки.

## Что правила не делают

Не утверждают причину, не советуют менять дизайн/цены, не используют исторические периоды до появления
целей, не считают события за визиты, не создают карточек при `BEHAVIOR_NOT_SYNCED`, `PERIOD_BEFORE_*`
и малой выборке.

## Порядок и идентификаторы

Карточки сортируются CRITICAL → ATTENTION → INFO. `id = <RULE>:<scope.kind>:<scope.key>` — стабилен
для одного и того же наблюдения в разных периодах (пригодится для подавления/подтверждения в будущих этапах).
