# Выкатка: репозиторий → сервер

```
git push (master)
    │
    ├─ GitHub Actions: тесты бэкенда и сборка панели
    │        │ упали — образы не собираются, сервер остаётся на старой версии
    │        ↓
    ├─ Сборка образов → ghcr.io/tigo929/racpechatca-{backend,frontend}
    │
    └─ Сервер, таймер раз в 5 минут:
           docker pull → образ изменился? → перезапуск → ждём healthy
```

Ничего нажимать не нужно. От `git push` до обновлённого сервера — примерно
5–12 минут: сборка плюс ожидание ближайшей проверки.

## Почему именно так

**Собираем не на сервере.** У сервера одно ядро и 1.6 ГБ памяти. Сборка
бэкенда занимала больше двадцати минут, и всё это время SSH почти не
отвечал — соединение рвалось само. Сайт (`web-photo`) этого не делает
с самого начала, теперь и CRM тоже.

**Сервер сам ходит в реестр, а не GitHub стучится к серверу.** Входящие
подключения к этому IP уже создавали проблемы: из-за них Telegram
пришлось перевести на long polling. Исходящий запрос в реестр работает
надёжно и не требует ни открытых портов, ни ключей в GitHub.

**Не нужен доступ к git с сервера.** Его убрали ради безопасности, и
выкатка CRM на этом встала. Теперь на сервере нет ни исходников, ни
доступа к репозиторию — только готовые образы.

**Панель собирается из исходников.** Раньше образ делался из готового
`dist`, которого нет в git: панель собирали локально и заливали отдельным
скриптом. Источник правды был вне репозитория — теперь он один.

## Как это устроено на сервере

| Что | Где |
|---|---|
| Скрипт | `/opt/deploy/auto-update.sh` |
| Таймер | `auto-update.timer`, каждые 5 минут и через минуту после загрузки |
| Журнал | `/var/log/auto-update.log` |

Скрипт сверяет идентификатор запущенного контейнера с идентификатором
свежескачанного образа. Это важно: `docker compose up -d` однажды уже
пропустил обновление `photo-web`, и прод молча отставал от репозитория на
несколько сборок.

После перезапуска скрипт ждёт, пока контейнер станет `healthy`, и пишет в
журнал, если тот не поднялся.

## Команды

```bash
# что происходило
tail -30 /var/log/auto-update.log

# обновиться немедленно, не дожидаясь таймера
/opt/deploy/auto-update.sh

# расписание
systemctl list-timers auto-update.timer

# временно остановить автообновление (например, на время разбора аварии)
systemctl stop auto-update.timer
```

## Откат

Образы помечены не только `latest`, но и хешем коммита. Чтобы вернуться
к конкретной версии:

```bash
systemctl stop auto-update.timer   # иначе таймер вернёт latest обратно
cd /opt/raspechatka
docker compose -f docker-compose.prod.yml down backend
docker run ... ghcr.io/tigo929/racpechatca-backend:<хеш-коммита>
```

Проще и правильнее — откатить коммит в репозитории: сборка пройдёт заново,
и сервер подхватит исправленную версию сам.

## Чего в цепочке пока нет

- Тесты фронтенда CRM (их не существует) — в CI только сборка.
- Уведомление о неудачном обновлении приходит только в журнал.
- Миграции базы применяются при старте бэкенда (`prisma migrate deploy`).
  Несовместимая миграция уронит контейнер, и автообновление это покажет,
  но откатить базу само не сможет.
